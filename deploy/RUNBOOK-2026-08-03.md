## Rollback

A release is a directory of files, so rollback is a redeploy of the previous `out/`.

| Failure | Action |
|---|---|
| The route shell is wrong | `ROUTES_ENABLED = false` in `src/lib/flags.ts`, rebuild, redeploy |
| A content defect | Revert the JSON commit, rebuild, redeploy |
| Anything else | `git checkout <prev>`, `npm run build`, `cd deploy && ./deploy.sh` |

No stored-progress migration to undo: every `Progress` field this transformation adds is
optional and defaults to empty, so a learner returning with an old save loses nothing.

**One behavioural change will read as a restriction.** The checkpoint attempt cap now
survives a refresh. It used to live in React state, and within six reloads 28 of 35
checkpoints cleared. Anyone who had been re-rolling a checkpoint with F5 can no longer do
that; that is the defect being fixed.

## Known residual risk

- **No visual regression baseline.** 110 browser tests assert structure and reachability, not pixels. A CSS regression that preserves the DOM passes everything. Highest residual risk.
- **No telemetry** (0 tracking calls), so the rollout is judged by looking. If the route split confuses learners, nothing reports it.
- **6.1 MB of assets** with no CI size budget.
